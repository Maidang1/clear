# ADR 0002：本地数据与主动更新边界

- 状态：已接受
- 日期：2026-07-31
- 决策来源：[定义本地历史、诊断数据与主动更新检查模型](https://github.com/Maidang1/clear/issues/9)

## 背景

Clear 需要显示历史、在崩溃后核对安全事务、支持用户导出诊断，并允许用户主动检查 GitHub Releases。它同时承诺本地分析和零遥测，因此必须限制持久化内容、保留时间和网络请求。

## 决策

Clear 不发送遥测，也不提供“匿名诊断共享”开关。所有持久化数据写入当前用户的 Application Support 目录，目录权限为仅当前用户可访问；使用带版本的 schema、原子替换和有界存储。

### 数据分类与保留

| 数据 | 内容 | 保留 |
| --- | --- | --- |
| 设置 | 扫描范围、阈值、菜单栏和 UI 偏好 | 直到用户重置或卸载 |
| 事务日志 | 未完成事务 reconcile 所需的最小目标身份、阶段和逐项结果 | 未完成时不可由普通“清除历史”删除；完成 reconcile 后进入 90 天上限 |
| 处理历史 | 操作类型、时间、结果计数、影响摘要、错误分类和恢复可用性 | 90 天或 500 条，先到为准 |
| 恢复定位信息 | 原路径和最后已知废纸篓位置等敏感字段 | 最长 30 天；用户可提前清除，未完成 reconcile 所需字段除外 |
| 诊断历史 | 每模块状态、数据质量、发现数量和少量聚合指标 | 细粒度 48 小时，小时聚合 30 天 |
| 最近状态 | 每模块最后一次成功观测的摘要和时间 | 被新观测覆盖；启动后必须标为“上次数据”直到刷新 |
| 运行日志 | 结构化错误类别、阶段、耗时和资源预算事件；默认不含完整路径或进程清单 | 7 天且总量不超过 5 MiB |

完整文件候选、完整进程列表、用户文档路径、文件内容和可重建原始扫描结果不做长期持久化。

### 导出

- 导出只能由用户主动发起，先生成可预览的带 schema 版本 JSON。
- 默认导出经过脱敏：用户目录替换为 `$HOME`，文件名和 bundle ID 对问题无必要时哈希或省略。
- 用户可显式选择“包含完整本地路径”，界面必须列出将包含的敏感字段。
- 导出文件只写到用户选择的位置；Clear 不上传、不自动分享。

### 清除

- “清除历史与诊断数据”删除处理历史、诊断历史、已完成事务日志、运行日志、更新缓存和可删除的恢复定位信息。
- 未完成事务日志保留到 reconcile 并向用户解释原因；完成后可再次清除。
- “恢复默认设置”与“清除历史与诊断数据”是两个独立动作。

### 主动更新检查

- 仅在用户点击“检查更新”时访问 GitHub Releases；不在启动、后台守护或定时任务中自动请求。
- 请求仅包含 HTTPS 所需信息、明确的 Clear 版本 User-Agent 以及缓存协商头。GitHub 仍会自然看到来源 IP，这一点在隐私说明中公开。
- 本地只保存检查时间、ETag、最新版本、发布页 URL、校验和 URL 和最近结果；30 天后或清除数据时删除。
- 不发送机器标识、硬件序列、用户名、安装 ID、扫描结果、架构统计或使用行为。
- 下载由用户明确发起。Release 应发布 Universal 包和 SHA-256 校验和；Clear 可以验证校验和，但未签名分发仍由用户手动信任。

## 备选方案

### 使用 UserDefaults 存放所有历史

拒绝。事务日志需要原子、版本化、可迁移和可审计的持久化边界，不能与偏好混在一起。

### 保留完整扫描结果以加速下次启动

拒绝。扫描结果会迅速过期并暴露文件和进程清单。Clear 应重新观测，并明确显示最后数据的时间与完整性。

### 默认或定时检查更新

拒绝。它违反“仅用户主动检查”的共同原则，也会形成未明确发起的网络信号。

## 影响

- 删除现有 `sharesAnonymousDiagnostics` 设置及对应 UI；Clear 不提供任何遥测代码路径。
- 处理历史从 `UserDefaults` 迁移到版本化本地存储；迁移后删除旧键。
- 事务日志和用户历史必须分离，清除历史不能破坏崩溃 reconcile。
- 数据存储、导出和清除需要自动化测试，包括保留上限、迁移、损坏文件、脱敏和未完成事务保护。
