# Clear 1.0 完整清理套件主规格

- 状态：决策完成，等待按路线实现与发布验收
- 主地图：[Clear 1.0 完整清理套件：决策地图](https://github.com/Maidang1/clear/issues/2)
- 平台：macOS 14+，Swift 6 / SwiftUI，Universal `arm64 + x86_64`
- 分发：GitHub Releases，ad-hoc 完整性签名，不使用 Developer ID 或 Apple 公证

## 产品承诺

Clear 是面向开发者和进阶 Mac 用户的本地系统健康工具。它先展示可观察事实、数据范围、影响和风险，再允许用户发起一个明确、安全、可核对结果的动作。

Clear 1.0 不承诺“一键清空内存”、固定释放空间、健康总分或自动优化。它不安装 root Helper、不使用私有 API、不上传遥测，也不在后台自动强退应用、删除文件、禁用启动项或卸载应用。

## 1.0 用户闭环

1. 打开主窗口后看到四模块健康概览；
2. 默认展开当前最值得关注且有新鲜证据的模块；
3. 查看状态句、关键证据、数据完整性、观测时间与一个安全下一步；
4. 进入模块详情，刷新或查看候选；
5. 对副作用查看不可变预览，明确确认；
6. Clear 执行前复验，逐项操作并独立验证；
7. 用户看到成功、部分完成、失败或不确定结果，以及每项恢复路径。

没有可安全执行动作时，下一步是刷新、理解权限、在 Finder 中查看或交接到系统设置；Clear 不伪造“已处理”。

## 信息架构

### 主窗口

主窗口由四部分组成：

- 侧栏：健康概览、内存中心、安全磁盘清理、启动项、应用卸载、历史与设置；
- 顶部态势矩阵：四个 `ModuleDigest`，显示关注级别、状态句、完整性和时间；
- 当前模块详情：诊断证据、范围、影响与候选；
- 事务区域：统一预览、确认、进度、逐项结果和恢复。

健康概览不显示总分。默认展开顺序为新鲜的 `actNow`、新鲜的 `review`、阻止判断的数据缺口、`observe`、完整且新鲜的 `clear`；用户手动选择后，后台刷新不抢焦点。

### 菜单栏

菜单栏默认关闭，可由用户开启。它与主窗口同进程，仅显示最高关注模块、数据时间和打开主窗口/刷新入口。安静状态不扫描磁盘、不盘点应用、不修改系统；后台永远不能创建已确认的安全事务。

## 统一安全事务

所有副作用遵守 ADR 0001：

`previewed → confirmed → preflighting → executing → verifying → completed | partiallyCompleted | failed | uncertain`

预览绑定目标身份、观测代次、证据、预期影响、权限、风险和恢复路径。确认只对该摘要有效。首次副作用前复验；每项副作用前写 journal 意图；执行返回值之外再观察结果。`uncertain` 立即停止尚未开始的操作。启动后只 reconcile 未完成 journal，绝不自动重放。

正常退出应用、系统设置交接等前置动作与最终文件事务分开显示。用户取消只阻止尚未开始的项目，不抹去已发生的结果。

## 权限与信任

基础功能保持当前用户权限。FDA 是用户主动开启的高级能力，只改善既有精确范围的可见性，不新增敏感清理规则，也不提高应用资产归属等级。

Clear 不显示全局“FDA 已开启”。能力按资源探测并记录为已覆盖、权限拒绝、不存在、接口缺口或暂时错误。权限变化会使相关快照和事务预览过期。

GitHub Release 使用 ad-hoc 完整性签名。安装文档要求用户在系统设置中手动信任并核对 SHA-256；不建议关闭 Gatekeeper/SIP 或批量删除 quarantine。更新后可能需要重新信任和重新授权。

## 本地数据与隐私

零遥测，没有匿名诊断开关。网络只在用户点击“检查更新”时访问 GitHub Releases。

设置、事务 journal、处理历史、诊断历史、最近摘要和运行日志按 ADR 0002 分开存储。完整候选清单、进程清单、用户文档路径和文件内容不长期保存。导出由用户主动发起、先预览、默认脱敏。

## 架构

保持 `ClearCore → ClearMac → ClearApp`：

- `ClearCore` 定义 observation、finding、digest、事务、journal、历史与排序；
- `ClearMac` 实现公开 macOS 观测、能力探测和副作用适配器；
- `ClearApp` 负责单一 composition root、SwiftUI 页面、菜单栏和统一事务界面。

四模块通过 `ModuleDigest` 汇入健康概览，不互相调用具体实现。扫描由页面可见性、用户刷新或根变化驱动，均可取消、有预算。睡眠停止采样；唤醒创建新 observation generation。

## MVP 迁移

现有内存与磁盘 MVP 不是重写起点：

- 保留 `SystemMemorySampler`、运行应用枚举、默认清理规则、路径安全策略和本地废纸篓文件系统；
- 移除匿名诊断偏好、私有进程 footprint 排名和强退能力；
- 修正 speculative page 重复计入可用内存的问题；
- 将 `CleanupCoordinator` 的 plan/execute 迁移到统一事务预览与逐项 journal；
- 将现有 `RootView` 的独立入口迁移为健康概览加模块详情；
- 将 `UserDefaults` 历史迁移到版本化本地存储，设置仍保留在 `UserDefaults`；
- 旧历史只能迁移为不含敏感目标的聚合结果；无法可靠解释的数据丢弃并记录一次本地迁移结果。

迁移期间不得同时维护两套执行入口。某个模块切换到统一事务后，旧直接执行 API 只保留内部适配或删除。

## 1.0 发布门槛

以下项目全部阻断发布：

- 零静默数据损失、错误目标和虚假成功；
- CI 全部通过，事务状态机、路径逃逸、身份漂移、权限拒绝、取消、`uncertain`、reconcile 与数据迁移有自动化测试；
- 四模块各完成可靠观测、可解释诊断、明确下一步、结果验证或恢复以及权限降级；
- Release Universal DMG 与 SHA-256 可复现生成；
- Intel 与 Apple Silicon 真机覆盖四模块关键流程、首次信任、权限授予/拒绝/撤销、升级、睡眠/唤醒与崩溃恢复；
- 两类机器的菜单栏分别连续运行至少 72 小时，无崩溃、持续内存增长或资源超标；
- 菜单栏安静状态 CPU median ≤ 0.2%、p95 ≤ 1%、steady physical footprint ≤ 50 MiB；
- 内存中心可见时 CPU median ≤ 2%、p95 ≤ 8%、steady physical footprint ≤ 80 MiB。

本地验收数据不上传。只有不影响安全、结果正确性、关键流程、双架构兼容和资源预算，并有明确规避方式的轻微 UI/文案缺陷可以延后。

## 明确不做

- Developer ID、公证、Mac App Store、Windows/Linux/iOS/iPadOS；
- root Helper、私有 API、修改其他进程内存、常态调用 `purge`；
- 健康总分、内存释放承诺、恶意软件判断；
- 后台自动副作用、永久删除、清空废纸篓、批量卸载；
- 删除用户文档、共享数据、宽泛 Application Support、容器或 App Group；
- 第三方启动项直接开关、厂商卸载脚本自动执行；
- 云账户、跨设备同步、遥测和自动更新检查。
