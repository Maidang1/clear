# Clear 1.0 应用卸载规格

- 状态：决策完成
- 地图：[Clear 1.0 应用卸载：决策地图](https://github.com/Maidang1/clear/issues/15)
- 研究：`docs/research/2026-07-31-application-asset-attribution.md`
- 依赖：ADR 0001、ADR 0002、ADR 0003

## 用户结果

用户从明确的第三方应用清单中选择一个应用，看到应用本体与少量可证明归属的可再生附属文件，主动决定哪些项目移入废纸篓，并得到逐项验证结果与人工恢复说明。Clear 不把用户数据、共享容器或模糊匹配包装成“残留清理”。

## 应用清单

只读枚举 `/Applications` 与 `~/Applications` 中的普通第三方 `.app` package。永久排除系统卷、Clear 自身、其他用户、外部卷、嵌套应用和非应用输入。

清单显示应用名称、图标、版本、bundle identifier、位置、包分配大小、架构兼容性和观测时间。应用大小只是当前文件系统分配估算，不包含用户数据，也不使用“上次使用”推断闲置。

损坏、不可读或无 bundle identifier 的应用可显示并允许在 Finder 中查看，但不能进入 Clear 1.0 卸载事务。系统应用、受 SIP 保护对象和来源不明对象不产生卸载候选。

## 归属等级

只有用户先选择一个可操作应用后，Clear 才扫描该应用的附属资产。候选按以下等级冻结证据：

1. `selectedAppBundle`：用户明确选择的应用包，默认选中；
2. `strongRegenerable`：精确 bundle identifier 根下的缓存和日志普通文件，默认选中；
3. `appSpecificSensitive`：精确 bundle identifier 的 Preferences，默认不选，并明确说明设置会被重置；
4. `userBearing`：Application Support、沙盒容器、Saved Application State 与可能承载用户内容的目录，永久排除；
5. `sharedOrAmbiguous`：App Group、共享容器、外部插件、框架、receipt 推断和仅凭名称/前缀匹配的项目，永久排除；
6. `blocked`：跨用户、跨卷、系统保护、符号链接、挂载点、身份不稳定或不可读对象，永久排除。

应用包内的 `PlugIns` 随应用本体作为一个 package 移动；安装在应用包之外的插件永不推断为该应用所有。FDA、App Management 或 POSIX 权限只影响可达性，不改变归属等级。

## 诊断与数据完整性

应用卸载不产生 `actNow`，不做恶意软件判断，也不建议批量“瘦身”。

- `review`：用户已经选择应用并存在可执行预览，或选中对象出现明确的身份、运行或权限阻塞；
- `observe`：完成应用清单盘点，但没有待确认的卸载事务；
- `undetermined`：两个应用根均不可读、盘点中断或超过预算。

未选择应用时只显示清单事实，不把安装数量或包大小解释为健康风险。清单全部覆盖且没有应用时可以显示 `clear`，文案限定为“已覆盖的应用目录中没有第三方应用”。

完整性按应用根、所选应用包和各附属规则分别记录。受阻范围不得被归并为“没有附属项目”；附属扫描超过 15 分钟或根发生变化后，预览标为 `stale`。

## 预览与选择

一次事务只处理一个应用。预览分为：

- 应用本体：package 路径、签名/标识证据、分配大小和运行状态；
- 默认附属项目：精确缓存与日志，显示重建成本；
- 可选敏感项目：Preferences，默认关闭并显示设置重置风险；
- 明确排除：用户承载、共享/歧义和受阻项目的分类、原因与覆盖。

用户必须逐次确认应用本体；不存在“全选应用”或批量卸载。附属项目不能脱离应用本体单独形成卸载事务。预览绑定所有项目的目标身份、归属等级、规则版本、估算大小、权限、运行状态与恢复方式。

## 运行应用交接

应用正在运行时不能执行。界面提供独立的正常退出请求，说明应用可能提示保存内容；Clear 不强退、不发送信号、不代替用户处理未保存数据。

应用退出后必须重新盘点、扫描并生成新预览。用户取消退出或应用仍运行时，事务保持未执行状态。

## 安全事务

确认后、首次副作用前，对所有选中项目一次性完成预检。任何项目的身份、归属、权限、卷或运行前置条件变化都使整份预览失效，不开始部分移动。

执行使用当前用户废纸篓，顺序固定：

1. 应用包作为不可拆分 package 移动；
2. 精确缓存与日志逐项移动；
3. 用户明确选择的 Preferences 最后移动。

每项遵守“写入 journal 意图 → no-follow 复验 → 移入废纸篓 → 验证原位置消失且废纸篓目标身份匹配 → 写入结果”。应用包在产生副作用前失败时，不处理任何附属项目；应用包成功后附属项目失败，结果为部分完成。任一项目进入 `uncertain` 后立即停止所有尚未开始的项目。

Clear 不执行厂商脚本、安装包反向操作、管理员卸载器或永久删除。权限不足只产生明确阻塞与系统位置说明，不触发提权。

## 结果与恢复

结果逐项显示：

- 已验证移入废纸篓；
- 复验后跳过；
- 明确失败；
- 不确定；
- 因取消未开始。

应用本体成功但附属项目未完成时，标题使用“应用已移入废纸篓，部分附属项目未处理”，不声称“完全卸载”。Clear 提供“在废纸篓中显示”、原位置和手动放回说明；如果用户已清空废纸篓，只能建议重新安装或从备份恢复。

Clear 1.0 不自动回滚、不自动重新安装，也不从历史重放移动。处理历史保留聚合结果 90 天或 500 条；敏感恢复定位最长 30 天；未完成 journal 保留到 reconcile。

## 资源与验收

- 应用清单最多 2,000 个 package；单个 package 元数据读取预算 1 MiB；附属扫描只使用内置精确规则，utility QoS、最多 2 路并发且可取消。
- 测试覆盖损坏/无标识应用、Clear/系统/外部卷排除、运行应用、精确与模糊归属、容器和 App Group 排除、Preferences 默认关闭、全量预检、package 移动、部分完成、`uncertain` 停止扩大、取消和 crash reconcile。
- Intel 与 Apple Silicon 共用归属、事务和恢复语义；分别真机验证 fat/thin 应用、正常退出、权限组合、废纸篓包移动和手动恢复。
